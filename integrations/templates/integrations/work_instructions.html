2. Welke rechten heb je nodig?

RolWat kun je doen?
Platformbeheerder met 2FADe gedeelde OAuth-client instellen en wijzigen via Integraties.

Het Google-account waarmee je koppelt moet toegang hebben tot de website in Search Console. De eigenaar van de koppeling moet ook in deze applicatie actief projectbeheerder blijven.

3. Google Cloud eenmalig instellen

Dit doet de beheerder van de OAuth-client. Gebruik voor alle onderstaande onderdelen hetzelfde Google Cloud-project. Controleer bovenaan in Google Cloud welk project is geselecteerd. De links kiezen waar mogelijk het projectnummer van de opgeslagen client.

  1. Open de Google Cloud Console. Maak of kies een project in de Google Cloud Console. Een project in Google Cloud is de technische configuratie; een project in deze website bevat je websitegegevens.
  2. Schakel de API in. Open Google Search Console API. Klik op Enable / Inschakelen. Staat er Manage / Beheren, dan is deze al actief. Een scope toevoegen activeert de API niet automatisch.
  3. Vul Branding in. Open Google Auth Platform → Branding. Vul de appnaam, het supportadres en de contactgegevens in die Google vraagt. Gebruik herkenbare gegevens, zodat gebruikers weten aan welke applicatie zij toegang geven.
  4. Stel Audience in. Open Audience. Kies External als accounts buiten je Google Workspace-organisatie moeten kunnen koppelen. Bij de status Testing: klik onder Test users op Add users en voeg precies het Google-account toe waarmee je gaat koppelen. Voor deze eerste test hoef je niet te publiceren. Voor langdurig gebruik: rond Branding af en beoordeel publicatie en eventuele verificatie bij Google. In testmodus verlopen de toestemming en het refresh-token voor deze scope na zeven dagen; opnieuw koppelen kan dan nodig zijn. Google-uitleg over Audience.
  5. Voeg de leesscope toe. Open Data access → Add or remove scopes. Plak onder Manually add scopes de onderstaande waarde. Klik Add to table → Update → Save.
    https://www.googleapis.com/auth/webmasters.readonly
    Deze applicatie gebruikt geen Drive-, Docs- of Gmail-scopes. Verwijder andere scopes alleen als geen andere applicatie in dit Cloud-project ze nodig heeft. Google-uitleg over Data access.
  6. Maak een OAuth-client. Open Clients → Create client. Kies Web application en geef de client een herkenbare naam. Authorised JavaScript origins mag voor deze serverkoppeling leeg blijven. Voeg onder Authorised redirect URIs exact deze URL toe:
    {{ redirect_uri }}
    Behoud https en de afsluitende slash. Klik Create of Save.
  7. Bewaar de clientgegevens. Kopieer de volledige client-ID (eindigt op .apps.googleusercontent.com) en het bijbehorende client secret naar de website. Gebruik beide waarden van dezelfde client. Een gemaskeerde waarde met sterretjes is niet het volledige secret. Ben je het secret kwijt, maak bij diezelfde client een nieuw secret en werk de website bij.

5. Koppel je account en kies de property

  1. Open je project → {% if project %}Koppelingen{% else %}Koppelingen{% endif %}.
  2. Klik Verbinden met Google en kies het account met Search Console-toegang. In testmodus moet dit account ook bij Test users staan.
  3. Geef toestemming voor het bekijken van Search Console-gegevens. Je Google-wachtwoord voer je alleen bij Google in.
  4. Na terugkeer kies je de property die bij de website van het project hoort.
  5. Klik Property koppelen en dagelijkse import inschakelen. De verbinding staat nu op Gekoppeld. De selectie zet dagelijkse imports aan.

Domain property: sc-domain:voorbeeld.nl omvat het domein met subdomeinen en protocollen. URL-prefix property: https://www.voorbeeld.nl/ geldt voor dat specifieke URL-voorvoegsel. Kies bewust de property die jouw website dekt; een https-property dekt niet automatisch de http-variant.

Koppelen alleen importeert niet onmiddellijk alle historie. Start voor direct resultaat een handmatige prestatie-import. De dagelijkse planning begint bij een volgende planningscontrole.

6. Haal de eerste zoekprestaties op

  1. Open bij de actieve koppeling het formulier met Vanaf en Tot en met.
  2. Kies een periode van 1 tot en met 31 dagen, inclusief beide datums. Voor een eerste controle kun je zeven dagen kiezen die eindigen op drie dagen geleden.
  3. Klik Gegevens ophalen. Elke opdracht maakt een aparte importbatch.
  4. Volg de batch via {% if project %}Bronnen & imports → Google Search Console{% else %}Bronnen & imports met bron Google Search Console{% endif %}. Open de batch en klik zo nodig Vernieuwen.
  5. Controleer de status, rapportageperiode, het aantal records en eventuele waarschuwingen. Bij Voltooid staan de gegevens in de bronrecords van de batch.
StatusBetekenis en actie
Wacht op verwerkingDe opdracht staat klaar. Wacht kort en vernieuw de batchpagina. Blijft dit aanhouden, laat de beheerder de verwerking controleren.
Wordt verwerktDe import loopt op de achtergrond. Vernieuw om de laatste status te zien.
VoltooidDe ontvangen bronrecords zijn gepubliceerd. Lees ook eventuele waarschuwingen over volledigheid.
MisluktLees de foutmelding, los de oorzaak op en klik als bewerker of beheerder Opnieuw starten.

Er worden alleen definitieve webzoekprestaties opgehaald, gegroepeerd naar pagina en dag. Recente dagen kunnen ontbreken. Een lege import bewijst niet dat de koppeling defect is of dat de pagina niet geïndexeerd is.

7. Dagelijkse imports beheren

De projectbeheerder gebruikt bij de koppeling Dagelijkse import inschakelen of Dagelijkse import uitschakelen. De knop noemt de actie: als er Uitschakelen staat, staat de planning dus aan.

OnderdeelHuidige instelling
Controle van de planningIeder uur; maximaal één nieuwe geplande batch per koppeling en Google-datum.
Opgehaalde periodeZeven dagen, eindigend drie dagen vóór de Google-datum van vandaag. De overlap neemt later definitief geworden data mee.
VoorbeeldIs het in de Google-tijdzone 20 november, dan loopt de periode van 11 tot en met 17 november.
HerkenningIn Bronnen & imports begint de naam met GSC dagelijkse import.
Na inschakelenEen batch verschijnt bij de volgende planningscontrole; de uitvoering volgt daarna op de achtergrond.
Na uitschakelenEr worden geen nieuwe dagelijkse batches gepland. Een al gestarte of eerder ingeplande import kan nog afronden. Historie blijft behouden.

De periode en frequentie zijn vaste instellingen van deze versie; je kunt in de website de planning aan of uit zetten. Gebruik een handmatige import voor een andere periode. Geplande batches die wachten of mislukken worden bij volgende controles opnieuw aangeboden zolang de planning en koppeling actief blijven.

8. Resultaten bekijken

Open Bronnen, selecteer een GSC-import en bekijk de bronrecords. Elke batch bewaart de property, gebruiker, importtijd en aangevraagde periode.

9. Selectieve URL-inspecties uitvoeren

Open Koppelingen en voer bij URL’s inspecteren maximaal twintig volledige URL’s binnen de gekoppelde property in. Open na verwerking de inspectiebatch om de bronrecords te bekijken.

InspectieveldWat controleer je?
Google-indexstatusGoogles algemene oordeel over indexering. Lees de indexeringsreden erbij voor context.
GSC-indexeringsredenDe uitleg die Google geeft over de gevonden of geïndexeerde pagina.
Robotsstatus / indexeringsregelsOf Google blokkades door robots.txt of noindex meldt.
OphaalstatusOf Google de pagina bij de bekende crawl kon ophalen.
Laatst gecrawld volgens GoogleHet door Google gemelde crawltijdstip. Dit is niet hetzelfde als de datum waarop jij de inspectie start.
Opgegeven canonicalDe canonical die Google bij de pagina heeft waargenomen.
Door Google gekozen canonicalDe URL die Google als voorkeursversie heeft gekozen. Vergelijk deze met de opgegeven canonical en de technische crawl.

Dit is een snapshot van Googles bekende indexgegevens, geen live test. De koppeling dient geen indexeringsverzoek in en wijzigt niets bij Google. Na een websitewijziging kan het even duren voordat Google de nieuwe toestand heeft gecrawld. Inspecties worden alleen op aanvraag uitgevoerd; de dagelijkse prestatie-import inspecteert geen URL’s. Google-documentatie over URL Inspection.

10. Vaste werkwijze en onderhoud

  • Na het koppelen: haal een korte periode handmatig op, controleer de bronrecords en inspecteer enkele belangrijke pagina’s.
  • Regelmatig: controleer bij Bronnen & imports of dagelijkse batches Voltooid zijn en lees waarschuwingen.
  • Bij een daling of canonicalvraag: kies de betrokken URL’s voor inspectie en vergelijk de Google-snapshot met een recente technische crawl. Trek geen conclusie uit één ontbrekende prestatierij.
  • Opnieuw koppelen: gebruik Verbinden met Google als Google-toestemming is verlopen of ingetrokken. Kies opnieuw de juiste property. Controleer daarna dat één bedoelde koppeling de dagelijkse imports uitvoert; schakel oude of dubbele koppelingen uit om dubbele importreeksen te voorkomen.
  • Google ontkoppelen: de projectbeheerder wist daarmee het lokale refresh-token en zet de planning van die verbinding uit. Bestaande imports blijven staan. Dit trekt niet automatisch de Google-toestemming voor andere projecten in. Bekijk die eventueel in je Google-accountverbindingen.
  • Een batch verwijderen: open de betreffende import en gebruik als projectbeheerder Verwijderen. Alleen die batch en zijn bronrecords verdwijnen; de GSC-koppeling en andere batches blijven bestaan.
  • Secret of client wijzigen: gebruik als platformbeheerder de Google-instellingen. Een ander client-ID vraagt opnieuw koppelen. Een nieuw secret voor dezelfde client-ID behoudt de bestaande koppelingen, zolang het secret geldig is.

11. Problemen oplossen

Melding of situatieControle en volgende stap
Google-koppeling niet beschikbaarLaat de platformbeheerder de client-ID, het secret en Google-koppeling beschikbaar stellen controleren in Integraties.
redirect_uri_mismatchOpen Clients en vergelijk exact met {{ redirect_uri }}. Sla op en start opnieuw vanuit Koppelingen.
Google weigert de OAuth-client / invalid_clientControleer of client-ID en het volledige secret bij dezelfde Web application horen. Sla het juiste secret opnieuw op in de website.
Toegang geweigerd / access_deniedControleer Audience → Test users, het gekozen account en de toestemming. Een Google Workspace-beheerder kan toegang ook beperken.
Search Console API staat niet aanOpen de API-pagina in hetzelfde Cloud-project als de client. Kies Enable, wacht enkele minuten en start opnieuw.
Search Console-leestoegang ontbreektControleer de scope onder Data access en geef bij een nieuwe koppeling toestemming voor Search Console.
Geen toegankelijke propertiesOpen Search Console met hetzelfde Google-account. Laat de eigenaar toegang geven tot de gewenste website. Een testgebruiker bij OAuth is niet automatisch een gebruiker van een GSC-property.
OAuth-sessie verlopen, invalid_grant of ongeldige stateGa terug naar Koppelingen en begin opnieuw. Vernieuw de callbackpagina niet. De koppelstap verloopt na tien minuten; bij testmodus kan blijvende toestemming ook na zeven dagen verlopen.
Lege of ontbrekende zoekprestatiesControleer property, periode, batchstatus en filters. Kies een oudere periode. Er kunnen geen vertoningen zijn; de API levert bovendien geen gegarandeerd volledige dataset.
URL valt buiten de propertyControleer het protocol, de host en het propertyvoorvoegsel.
Google API-limiet bereiktWacht en probeer later opnieuw. Inspecteer alleen de URL’s die je nu nodig hebt; start niet steeds dezelfde selectie.
Projecttoegang of bronverbinding ingetrokkenControleer dat de uitvoerder nog bewerker/beheerder is en de verbindingseigenaar nog actief projectbeheerder. Laat zo nodig opnieuw koppelen.
Dagelijkse batch verschijnt nietControleer de planningknop, actieve verbinding en rechten. Geef de volgende uurcontrole tijd. Blijft de batch uit, laat de platformbeheerder de achtergrondverwerking controleren.

Na het oplossen: start een Google-koppeling opnieuw via Verbinden met Google, of herstart een mislukte import via Opnieuw starten. Deel bij hulp de foutmelding en batchnaam; deel geen client secrets, OAuth-codes of tokens.

Deze instructie beschrijft de huidige versie van de GSC-koppeling. De frequentie, periodelimieten en interfacebenamingen zijn afgestemd op de applicatie.
